# Blackout mode — plan

Design: [`../specs/2026-09-02-blackout-design.md`](../specs/2026-09-02-blackout-design.md). Notion
task 19. No schema change.

## Step 1 — the confirmation lifecycle learns about order types

- `CartConfirmationService.present(User, List<ShoppingListItem>, OrderType)`; the two-argument overload
  stays and passes `INITIAL`.
- `confirm(...)` writes the baseline only for `INITIAL`. An emergency lunch is not a new normal.

## Step 2 — `service/BlackoutModeService`

- `NO_COOKING_NEEDED` — the curated list, one constant, readable.
- `buildBlackoutOrder(User)` — turns it into transient `ShoppingListItem`s and hands them to
  `present(..., AD_HOC)`.

## Step 3 — the trigger

`/blackout` in `TelegramRoutingService`, next to `/calendar`, for an onboarded user not mid-flow.

## Step 4 — tests

`BlackoutModeIntegrationTest`:

1. `/blackout` searches for the curated terms and nothing else;
2. the draft order is `AD_HOC`;
3. confirming it leaves the current baseline exactly as it was;
4. confirming it still stores a confirmed order and sends the checkout link.

## Step 5 — close out

README note, `make format`, `./gradlew test`, `./gradlew build`, commit, Notion (the manual
result-quality check stays unticked), ff-merge into `main`.
